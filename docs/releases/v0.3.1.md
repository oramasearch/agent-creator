# agent-creator v0.3.1

**Released 2026-11-16. A patch release.** One image, `docker.io/oramasearch/agent-creator:v0.3.1`,
built on [agent-runtime v0.3.1](https://github.com/oramasearch/agent-runtime/releases/tag/v0.3.1).

Since [v0.3.0](v0.3.0.md): one clean header in the Dockerfile. The definition itself (prompt, the
rule checks in `defects`, the turn answer, and how Lake reaches it) is unchanged, and so is the
runtime underneath: agent-runtime v0.3.1 changes only its own Dockerfile comments.

This release is the tree of `dev` after #32 (`dc435a4`), with these notes and the version.

### On agent-runtime v0.3.1, underneath

The image is `FROM oramasearch/agent-runtime:${RUNTIME_TAG}` built with `RUNTIME_TAG=v0.3.1`
([notes](https://github.com/oramasearch/agent-runtime/blob/v0.3.1/docs/releases/v0.3.1.md)). That
runtime release changes only Dockerfile comments; its code is v0.3.0's.

same as agent-runtime v0.3.1's `skills.json`.

## Known issues

Security-relevant first. Unchanged from v0.3.0.

1. **Build logs and App events go unbounded into the system prompt** and can steer the proposal
   (#22). The fix is #24, not in this release.
2. **The runtime writes every turn's trace to the shared pod's disk**
   ([agent-runtime#38](https://github.com/oramasearch/agent-runtime/issues/38)): one AgentCreator
   pod serves every tenant, so every tenant's turn content stays under `TRACE_DIR`.
3. **The image bundles GPL and LGPL code** (#28): it is built on agent-runtime's
   `python:3.12-slim` base (Debian: glibc, bash, coreutils, dpkg, readline). The move to `scratch`
   with static binaries is deferred; it is noted here and does not block this release.
4. **The runtime base is named by tag only** (#25, deferred): a later build of the same tree could
   get a different runtime if the tag moved.
5. **Workspace identity is not passed explicitly on every call** (#9, with
   [agent-runtime#6](https://github.com/oramasearch/agent-runtime/issues/6)): App and build reads
   carry only `customer_id`.
6. **The structured answer is shipped, the issue is still open** (#1), for Lake's side to read
   `result`.

## Where it has run

**The v0.3.1 tree had not run on a development environment when it was released.** Lakes take the
operator's default AgentCreator image; moving it to `:v0.3.1` is a separate operator change.

## The image

Built from the tag `v0.3.1` with BuildKit (linux/amd64, the repository's Dockerfile, on
`oramasearch/agent-runtime:v0.3.1` with `RUNTIME_TAG=v0.3.1`), then tagged `:v0.3.1` on that digest
without rebuilding. The digest is recorded here once it is built.
