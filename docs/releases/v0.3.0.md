# agent-creator v0.3.0

**Released 2026-11-16. A minor release.** One image, `docker.io/oramasearch/agent-creator:v0.3.0`,
built on [agent-runtime v0.3.0](https://github.com/oramasearch/agent-runtime/releases/tag/v0.3.0).

Since [v0.2.0](v0.2.0.md): the MIT licence, a security policy and the tree prepared for a public
export. Underneath, the agent-runtime it runs on bounds its bus consumer and conversation memory and
pins its base images by digest. The definition itself (prompt, the rule checks in `defects`, the
turn answer, and how Lake reaches it) is unchanged from v0.2.0.

This release is the tree of `dev` after #27 (`597250b`), with these notes and the version.

### The licence — #27

agent-creator is released under the MIT licence, copyright OramaSearch, Inc. (`LICENSE`,
`COPYRIGHT`). Every source file carries `SPDX-License-Identifier: MIT`, added and checked by
`tools/spdx-headers.py`. `THIRD_PARTY_LICENSES` lists the licence of every dependency. Contributions
are made under `CLA.md` (contributors assign copyright to OramaSearch, Inc.), following
`CONTRIBUTING.md` and `CODE_OF_CONDUCT.md`. `tools/sbom.py` writes the software bill of materials in
SPDX 2.3 and CycloneDX, regenerated for this release.

### From agent-runtime v0.3.0, underneath

The image is `FROM oramasearch/agent-runtime:${RUNTIME_TAG}` built with `RUNTIME_TAG=v0.3.0`, so it
carries every change in agent-runtime since its v0.2.0
([notes](https://github.com/oramasearch/agent-runtime/blob/v0.3.0/docs/releases/v0.3.0.md)):

- **the bus consumer claims a task only when a worker is free**, at most `AGENT_BUS_WORKERS`
  (default 4) at once and `AGENT_BUS_TENANT_WORKERS` (default one fewer) for one customer;
- **conversation memory is bounded** (`AGENT_CONVERSATIONS`, `AGENT_CONVERSATION_TURNS`,
  `AGENT_CONVERSATION_BYTES`, `AGENT_CONVERSATIONS_BYTES`, `AGENT_CONVERSATION_IDLE_SECONDS`), and a
  bus turn continues only the conversation its `prior_turn` left in the same account and workspace;
- **the runtime's base images are pinned by digest**;
- the runtime's MIT licence and security policy.

The vendored copy of agent-runtime's skills (`tests/fixtures/agent-runtime-skills.json`) is the
same as agent-runtime v0.3.0's `skills.json`.

## Known issues

Security-relevant first.

1. **Build logs and App events go unbounded into the system prompt** and can steer the proposal
   (#22). The fix is #24, not in this release.
2. **The runtime writes every turn's trace to the shared pod's disk** (agent-runtime#38): one
   AgentCreator pod serves every tenant, so every tenant's turn content stays under `TRACE_DIR`.
3. **The image bundles GPL and LGPL code** (#28): it is built on agent-runtime's
   `python:3.12-slim` base (Debian: glibc, bash, coreutils, dpkg, readline), so the image is not
   published. It moves with agent-runtime to `scratch` with static binaries before it is.
4. **The runtime base is named by tag only** (#25, deferred): a later build of the same tree could
   get a different runtime if the tag moved.
5. **Workspace identity is not passed explicitly on every call** (#9, with agent-runtime#6): App and
   build reads carry only `customer_id`.
6. **The structured answer is shipped, the issue is still open** (#1), for Lake's side to read
   `result`.

## Where it has run

**The v0.3.0 tree had not run on a development environment when it was released.** Lakes take the
operator's default AgentCreator image; moving it to `:v0.3.0` is a separate operator change.

## The image

Built from the tag `v0.3.0` with BuildKit (linux/amd64, the repository's Dockerfile, on
`oramasearch/agent-runtime:v0.3.0` with `RUNTIME_TAG=v0.3.0`), then tagged `:v0.3.0` on that digest
without rebuilding. The digest is recorded here once it is built.
